🌟 Visión General: Computación Cloud $0 con MockHive

              

                MockHive es la plataforma de infraestructura y computación en la nube del ecosistema Terra. Transforma el poder de cómputo de GitHub Actions en servidores interactivos bajo demanda, máquinas de estados serverless, funciones polyglot y clusters paralelos Map-Reduce sin intermediarios ni facturas mensuales.
              

              

                

                  
🔒 100% Privado y en tu Cuenta

                  

                    Tus tokens, scripts y datos se almacenan exclusivamente en tu navegador y en tu repositorio privado .mockhive-storage. Ningún dato pasa por servidores externos.
                  

                

                

                  
⚡ Ejecución Híbrida (Browser + Cloud)

                  

                    Simula y prueba flujos con latencia cero en el motor JavaScript del navegador y despacha tareas pesadas a runners de Ubuntu en la nube cuando sea necesario.
                  

                

              

            


            
            

              
🏰 HiveNodes: Servidores Virtuales y Terminal SSH

              

                Un HiveNode es una instancia Ubuntu 24.04 LTS real con 2 vCPU, 7 GB de RAM y 14 GB de SSD, provisionada sobre runners de GitHub Actions con persistencia configurable en /mockhive/data.
              

              

                

                  
🌐 1. Web Terminal Instantánea (xterm.js)

                  

                    Haz clic en 🚀 Abrir Terminal Web en el nodo activo. Se iniciará una sesión interactiva en tu navegador con soporte para colores ANSI, atajos de teclado y permisos completos de sudo.
                  

                


                

                  
💻 2. Conexión SSH Nativa por Puerto 443

                  

                    MockHive utiliza Cloudflare Tunnel para encapsular el tráfico SSH en HTTPS estándar (puerto 443), evitando bloqueos de routers o redes corporativas.
                  

                  
# Conectar desde cualquier terminal:
ssh runner@mockhive-tu-nodo.trycloudflare.com

                  Contraseña por defecto: mockhive2026 (o la configurada al crear el nodo).
                

              

            


            
            

              
⚠️ Ciclo de Vida & Modo 24/7 Lazarus Relay

              

                Los runners de GitHub Actions tienen un límite operativo de 6 horas por ejecución. MockHive ofrece dos modos de gestión del ciclo de vida:
              

              

                

                  
⏱️ Modo TTL Efímero (Recomendado)

                  

                    El servidor se apaga automáticamente tras $N$ minutos o tras un periodo de inactividad SSH. Es el modo óptimo para desarrollo, pruebas y ahorro de minutos.
                  

                

                

                  
🔄 Modo 24/7 Lazarus Relay

                  

                    Antes de alcanzar las 6 horas, el nodo empaqueta su almacenamiento en /mockhive/data, dispara un nuevo runner relevo y traspasa la sesión. Úsalo con moderación para cumplir con los Términos de Servicio de GitHub.
                  

                

              

            


            
            

              
🐝 Waggles: State Machines & Orquestación de Flujos

              

                Las Waggles permiten definir pipelines declarativos en formato ASL (Amazon States Language) con soporte para evaluación de ramas lógicas, pausas para aprobación humana y reintentos automáticos.
              

              

                

                  🔌 Conectores Reutilizables:
                  

                    Desacopla la lógica del flujo registrando conectores HTTP (APIs REST/GraphQL), Storage (S3, Rolla, Vault) o Code (Micro-scripts).
                  

                

                

                  ⏸️ Aprobaciones Human-in-the-Loop:
                  

                    Los estados tipo WaitForApproval pausan la ejecución y generan un token de reanudación hasta que un operador apruebe o rechace la acción desde la consola o el CLI.
                  

                

              

            


            
            

              
🌸 PollenPods: Micro-Handlers Serverless Polyglot

              

                Los PollenPods son funciones serverless compiladas y listas para ejecutarse bajo demanda en Python 3.11, Node.js 20, Rust 1.78, Go 1.22, WebAssembly (WASM) o Bash.
              

              
🚀 3 Vías de Invocación e Integración Externa:

              

                

                  1. Invocación Local mediante SDK o CLI:
                  
node bin/mockhive.js pods invoke pod_normalizer_py --payload '{"data": [1, 2, 3]}'

                

                

                  2. Endpoint HTTP en Tiempo Real (sobre HiveNode):
                  
Despliega un micro-servidor en un HiveNode activo para exponer tus pods como endpoints HTTP públicos con latencia inferior a 50 ms.

                

                

                  3. Invocación Asíncrona vía GitHub Dispatches ($0 Cost):
                  
Lanza ejecuciones serverless directamente contra la API de GitHub (`POST /repos/:owner/:repo/dispatches`) persistiendo el resultado en el Vault.

                

              

            


            
            

              
🕸️ HiveGrid: Cluster Distribuido Map-Reduce

              

                HiveGrid divide tareas computacionalmente pesadas entre matrices paralelas de 2 a 20 runners simultáneos con reducción automática de resultados.
              

              

                

                  
🔀 Estrategias de Particionamiento

                  
    
                    
  • Auto-Balanced: Reparto uniforme entre workers.
    • 
                    
  • Key-Hash: Hashing por clave para agrupaciones tipo Group-By.
    • 
                    
  • Range-Index: Fragmentación por bloques secuenciales.
    • 
                  

                

                

                  
🌳 Reducción Jerárquica en Árbol

                  

                    Consolida los resultados de los workers en árboles multinivel $O(\log N)$ para evitar saturar la memoria del nodo maestro.
                  

                

              

            


            
            

              
📦 Almacenamiento Persistente & Data Lake

              

                El almacenamiento en MockHive es agnóstico y desacoplado:
              

              
    
                
  • GitHub Storage Vault (.mockhive-storage): Almacenamiento versionado gratuito integrado con GitHub Releases y Git Database API.
    • 
                
  • Rolla Balls (rolla://...): Almacenamiento inmutable de objetos a coste $0 dentro del ecosistema Terra.
    • 
                
  • S3 Compatible (s3://...): Conexión directa a AWS S3, Cloudflare R2 o MinIO para datasets de gran volumen.
    • 
              

            


            
            

              
💻 SDK & CLI en Línea de Comandos

              

                MockHive incluye un CLI completo y un SDK en TypeScript compilado a ES Modules:
              

              
# Iniciar la consola local en puerto personalizado:
mockhive console --port 8999

# Despachar un cluster job Map-Reduce:
mockhive grid dispatch --name "Batch-Embedding" --workers 6 --runtime python3 --partition key_hash --reduce-tree tree

# Listar e invocar PollenPods:
mockhive pods list
mockhive pods invoke pod_crypto_rust --payload '{"data": "terra"}'

# Consultar inventario de servidores:
mockhive nodes list

            


            
            

              
💡 Buenas Prácticas de Rendimiento y Seguridad

              

                

                  
✔️ Recomendado

                  
    
                    
  • Utiliza siempre tokens de GitHub con los permisos mínimos necesarios (repo y workflow).
    • 
                    
  • Prueba la lógica de tus Waggles en modo Navegador antes de lanzar ejecuciones en Cloud Runner.
    • 
                    
  • Monta /mockhive/data para asegurar que tus dependencias instaladas no se pierdan.
    • 
                    
  • Usa particionamiento key_hash en HiveGrid cuando proceses transacciones o registros agrupables.
    • 
                  

                

                

                  
❌ A Evitar

                  
    
                    
  • No mantengas múltiples servidores 24/7 sin supervisión si no requieres disponibilidad ininterrumpida.
    • 
                    
  • No almacenes credenciales en texto plano; utiliza Secrets de GitHub o campos protegidos.
    • 
                    
  • No ejecutes reducciones monolíticas de payloads masivos sin activar el árbol jerárquico.
    • 
                  

                

              

            


            
            

              
❓ Preguntas Frecuentes (FAQ) & Resolución de Dudas

              
              

                

                  
1. ¿Cómo es posible que MockHive sea 100% a coste $0?

                  

                    MockHive aprovecha la cuota de minutos gratuitos de GitHub Actions y el alojamiento de GitHub Pages. No requiere servidores dedicados, bases de datos gestionadas ni intermediarios propietarios.
                  

                


                

                  
2. ¿Qué permisos exactos requiere mi GitHub Personal Access Token (PAT)?

                  

                    Únicamente requiere los scopes repo (para sincronizar con .mockhive-storage) y workflow (para lanzar runners de Actions bajo demanda).
                  

                


                

                  
3. ¿Mis credenciales o datos pasan por algún servidor externo?

                  

                    No, en absoluto. La consola web se ejecuta en el lado del cliente (navegador) y se comunica de forma directa y cifrada vía TLS con la API oficial de GitHub.
                  

                


                

                  
4. ¿Cuál es la diferencia entre PollenPods, Waggles y HiveGrid?

                  

                    • PollenPods: Funciones individuales sin estado para cálculos rápidos.

                    • Waggles: Grafos orquestados de múltiples pasos con ramificaciones lógicas y aprobaciones.

                    • HiveGrid: Computación paralela masiva en matriz para procesar grandes volúmenes de datos.
                  

                


                

                  
5. ¿Puedo conectar mi frontend o backend externo a un HiveNode o PollenPod?

                  

                    Sí. Puedes invocar pods mediante GitHub Dispatches vía REST API o exponer un túnel HTTP público con Cloudflare Tunnel en un HiveNode activo.
                  

                


                

                  
6. ¿Qué ocurre si un runner de GitHub Actions se apaga?

                  

                    Si el nodo tiene almacenamiento persistente configurado (Vault, Rolla o S3), el estado de /mockhive/data se almacena automáticamente y se restaura íntegro al volver a encender el nodo.
                  

                


                

                  
7. ¿Puedo ejecutar contenedores Docker propios en un HiveNode?

                  

                    Sí. El runner de Ubuntu incluye el demonio Docker preinstalado. Puedes ejecutar docker run, docker compose o compilar imágenes sin restricciones.
                  

                


                

                  
8. ¿Cómo funciona el árbol de reducción jerárquica en HiveGrid?

                  

                    En lugar de enviar todas las salidas a un único nodo final, HiveGrid agrupa las salidas intermedias por parejas en reducers de primer nivel antes de consolidar el resultado final en la raíz ($O(\log N)$).
                  

                


                

                  
9. ¿Cómo se integran las aplicaciones de Terra (Rolla, Mantx, Formica, Maskito)?

                  

                    Todas las aplicaciones de Terra comparten el protocolo de almacenamiento inmutable Rolla y los conectores HTTP universales de Waggles, permitiendo crear pipelines autónomos completos.
                  

                


                

                  
10. ¿Puedo ejecutar la consola en local con un puerto personalizado?

                  

                    Sí. Ejecuta mockhive console --port 8999 o mockhive serve --port 8999 para levantar el servidor web estático en cualquier puerto de tu máquina.
                  

                


                

                  
11. ¿Dónde se visualizan los logs de telemetría en tiempo real?

                  

                    En la pestaña Resource Monitor encontrarás el stream de eventos en vivo que registra las transacciones del Vault, lanzamientos de pods y estados de servidores.
                  

                


                

                  
12. ¿Qué ocurre si alcanzo el límite de concurrencia de GitHub Actions?

                  

                    GitHub Actions encolará automáticamente los jobs excedentes y los ejecutará en cuanto quede un runner libre, sin perder ningún parámetro ni estado del cluster.
